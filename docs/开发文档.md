# 🎙️ SayTopic — 开发文档

## 1. 项目概述

一个在线录音 + 图片上传 + 二维码声纹打印工具：
- 所有录音者依次使用同一台共享电脑录音，不需要用户名
- 录音完成后自动上传到服务器，返回可公开访问的 URL
- 录音完成后首页展示一个二维码（指向手机端图片上传页），用户扫码后在手机端上传图片，或在电脑上拍照；两种方式任选其一后可生成明信片
- 手机上传图片后，首页通过轮询实时同步显示图片
- 前端生成音频二维码（指向播放页面）+ 波形图，并导出 148mm×100mm 的打印版 PDF
- 手机播放页使用用户名记录去重后的已听数量，个人统计页可生成凭证图片

---

## 业务流程

### 共享电脑创作

- 所有录音者依次使用同一台电脑，不需要输入或保存用户名。
- 流程为：录音 → 电脑摄像头拍照或手机扫码上传图片 → 生成明信片 → 打开打印版 PDF → 调用系统打印。
- 打印版 PDF 成功打开后，网页自动清空本次录音、图片和界面状态，供下一位用户使用。
- 页面清空不删除服务器上的录音和图片，已打印明信片的二维码必须继续可用。

### 手机聆听

- 用户只能通过明信片二维码或活动方提供的单条录音链接进入，不提供录音浏览列表。
- 手机第一次播放前必须输入用户名；之后保存在该手机的 `localStorage`，并支持切换用户名。
- 用户名区分大小写，不使用密码或验证码；不同设备输入相同用户名时共享数据。
- 音频开始播放即记为听过；自己的录音也计入。
- 个人已听数量按“用户名 + 录音文件名”唯一组合去重，同一录音重复播放不增加数量。
- 播放页在播放前显示当前已听数量，首次播放新录音后实时更新，并提供“我的统计”入口。

### 个人统计与凭证

- `/mine` 只显示当前用户名和“已听 X 条录音”，不展示录音列表或单条播放次数。
- 用户点击生成凭证后，页面展示一张只含用户名和“已听 X 条录音”的图片，供手机长按保存。
- 系统不维护录音所有者查询或单条录音累计播放次数。

### 数据与活动边界

- 这是一次性活动，不需要多活动隔离或历史活动管理。
- 正式活动使用现有公网服务器；开始前备份并清空测试录音、图片和统计数据。
- 清空测试数据是单次运维操作，不提供公开的重置页面或 API，且必须由用户再次确认后执行。

## 4. 后端 API 设计

### 4.1 `POST /api/upload`

| 项目 | 内容 |
|------|------|
| Content-Type | `multipart/form-data` |
| 参数 | `file` — 录音文件（m4a/webm/ogg；后端也接受 mp3/wav） |
| 成功响应 | `{ "url": "/api/audio/xxx.m4a", "filename": "xxx.m4a" }` |
| 错误响应 | `{ "detail": "..." }` |
| 逻辑 | 保存到 `uploads/`，用 UUID 重命名，保留原始扩展名 |

### 4.2 `GET /api/audio/{filename}`

| 项目 | 内容 |
|------|------|
| 响应 | 音频二进制流（根据扩展名自动设置 Content-Type） |
| 逻辑 | 读取 `uploads/{filename}` 返回文件流 |

### 4.3 个人已听统计

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/listening-stats?username={username}` | 查询用户名听过的不同录音数量 |
| POST | `/api/audio/{filename}/play?username={username}` | 记录已听并返回最新 `listened_count` |

个人已听记录保存在 `backend/uploads/stats.sqlite3`，按“用户名 + 录音文件名”唯一约束去重。用户名区分大小写，长度为 1–40 字符。

### 4.4 `POST /api/upload-image`

| 项目 | 内容 |
|------|------|
| Content-Type | `multipart/form-data` |
| 参数 | `file` — 图片文件（jpg/jpeg/png/webp）；`audio_filename` — 可选，关联的音频文件名（提供时图片以音频基名+图片扩展名命名） |
| 成功响应 | `{ "url": "/api/image/xxx.{ext}", "filename": "xxx.{ext}" }` |
| 错误响应 | `{ "detail": "..." }` |
| 逻辑 | 保存到 `uploads/`，若提供 `audio_filename` 则以音频基名命名图片，否则用 UUID |
| 限制 | 最大 10MB，支持格式：jpg/jpeg/png/webp |

### 4.5 `GET / HEAD /api/image/{filename}`

| 项目 | 内容 |
|------|------|
| 方法 | GET, HEAD |
| 响应 | 图片二进制流（根据扩展名自动设置 Content-Type），HEAD 返回不含 body 的响应头（用于轮询检测） |
| 逻辑 | 读取 `uploads/{filename}` 返回文件流 |

### 4.6 CORS

当前允许前端开发服务器（`http://localhost:5173`）和 `https://frp-off.com:23506` 跨域访问。新增穿透域名时，也要在 `frontend/vite.config.js` 的 `allowedHosts` 中加入对应主机名。

## 6. 前端组件详情

### 6.1 `AudioRecorder.vue`

- 复古电话亭造型：天线、圆顶（SAY TOPIC 标签）、金属质感主体、底座
- LED 状态指示灯（等待/录音中/完成三种状态）
- 使用浏览器 MediaRecorder API 进行录音
- 浏览器优先使用 `audio/mp4`，上传时保存为 `.m4a`（iOS 兼容），其次为 webm/ogg
- 界面提示录音时长 30-60 秒，带进度条，到 60 秒自动停止；用户可提前停止
- 脉冲环动画 + 麦克风图标（录音中）/ 浮动动画（等待）
- 录音完成后显示回放音频控件
- 上传按钮文案为"生成明信片"，emit `url` 和 `filename` 给父组件

### 6.2 `WaveformCanvas.vue`

- Props: `audioUrl`（必填）、`height`（默认 200）、`width`（默认 600）、`colorTheme`（`card`/`primary`/`coral`）
- 使用 `AudioContext.decodeAudioData()` 解码音频
- 在 Canvas 上绘制波形（时间-振幅），带填充渐变和中线虚线
- 每个主题包含 `line`、`fill`、`bg`、`midLine` 四项；`card` 主题供明信片使用：深灰线条 `#333333`、填充同色 12%、中线同色 25%、背景透明
- 响应式，尺寸适配明信片打印比例

### 6.3 `QrCodeCard.vue`（打印核心）

- 使用 `mingxinpian.jpg` 作为底图，绝对定位叠加元素
- 尺寸：148mm × 100mm（标准明信片尺寸）
- 底图已预处理为 2500 × 1689（即 148:100），CSS 与 PDF 都直接拉满，不需要裁切或拉伸补偿
- 三个区域坐标只维护一份：脚本里的 `CARD_REGIONS`，HTML 预览通过内联 `style` 使用，打印 PDF 通过 `regionRect()` 换算成像素，避免两份参数不一致
  - 图片区：`left: 12.664%`, `top: 20.833%`，宽 `27.138%`、高 `45.037%`（坐标沿用带虚线框的旧底图）；新底图已去掉蓝色虚线框，组件也不额外绘制边框，因此照片区没有框线，`contain` 留白直接露出纸纹
  - 波形区：右列「录制你的语音」标签下方（`left: 51.85%`, `top: 58.8%`，宽 `41.94%`、高 `11.5%`，约 62mm × 11.5mm）
  - 二维码：底图灰色方块内（`left: 51.85%`, `top: 29.04%`，宽 `15.83%`、高 `23.16%`）；先铺白底再居中放二维码，保证静区完整
- 照片按 `contain` 完整显示，不裁切；摄像头是 4:3 横图、底图框是竖框，因此照片上下会留出空白，这是「不裁剪」的必然结果
- 打印按钮在组件外部，打印时隐藏
- Props: `audioUrl`, `filename`, `imageUrl`（可选）
- 生成**一个**二维码（音频播放链接）
- 点击打印按钮后，将明信片合成到 Canvas，并打开单页 PDF 预览；PDF 成功打开后触发 `printed` 事件重置首页
- ⚠️ 明信片上**不包含**图片上传二维码

### 6.4 `ImageUploadView.vue`

- 从路由参数获取 `audioFilename`
- 移动端优化界面，支持拍照和相册选择
- 使用 `<input type="file" accept="image/jpeg,image/jpg,image/png,image/webp">`，**不写 `capture` 属性**：一旦写了 `capture`，移动端浏览器会跳过系统选择面板直接打开相机，相册入口就没了；不写时系统会弹出「拍照 / 相册 / 文件」三种选择
- 页面内置图片选择、校验、预览和上传流程
- 上传成功后显示成功提示
- 简洁页面，适合移动端扫码浏览
- 上传时携带 `audioFilename` 参数，后端以音频基名+图片扩展名命名，实现文件名关联

### 6.5 `PlayView.vue`

- 从路由参数获取 `filename`
- 构建音频 URL：`/api/audio/{filename}`
- 使用浏览器原生 `<audio controls>` 播放
- 当前浏览器没有用户名时先要求输入，并保存到 `localStorage`
- 页面加载时查询当前用户听过的不同录音数量，首次实际播放后刷新该数量
- 首次播放同时记录个人已听条目，相同用户名重复听同一录音仍只计一条
- 提供“我的统计”入口和切换用户名按钮
- 简洁页面，适合移动端扫码浏览

### 6.6 `MyStatsView.vue`

- 从 `localStorage` 读取当前用户名
- 调用 `GET /api/listening-stats` 展示听过的不同录音数量
- 支持切换用户名
- 使用浏览器原生 Canvas 生成只含用户名和已听数量的 PNG 图片
- 页面展示生成图片，供手机长按保存

### 6.7 `HomeView.vue` — 首页完整流程

首页是**单屏不滚动**的横向两栏布局：左栏固定是电话亭录音组件，右栏在「图片上传」与「明信片」之间切换。背景是渐变 + 校园楼宇线稿 + 左右两列毛笔艺术字。完整设计依据见 [首页单屏改造方案](首页单屏改造方案.md)。

- 舞台结构：`.home`（`position: fixed; inset: 0; overflow: hidden`，背景透出 `body` 的 `--bg-gradient`）→ `.bg-building`（校园楼宇线稿，底部对齐、全屏宽）→ `.bg-text`（左右两列竖排艺术字：左列「立德思源」、右列「感恩笃行」，右列整体下移 110px，马善政毛笔楷书 + 蓝金竖向渐变）→ `.bg-decor`（三个浮动光斑）→ `.stage` → `.split`（两栏各 50%）。同 z-index 时后写的在上层，所以艺术字会压住楼宇线稿
- 「声音家书」徽章固定顶部居中（`top: 24px`）、页脚「SayTopic - 声音家书，传递感恩」固定底部居中（`bottom: 16px`），都是绝对定位，不参与单屏布局、不产生滚动高度
- `step` 状态机取 `record` / `image` / `card`：

  | step | 左栏 | 右栏 | `.split` 位移 | 右栏可见性 |
  |---|---|---|---|---|
  | `record` | 电话亭 | 空 | `translateX(25%)`（电话亭居中） | `opacity: 0`，右移出屏 |
  | `image` | 电话亭 | 图片上传 | `translateX(0)` | 显示 |
  | `card` | 电话亭 | 明信片 | `translateX(0)` | 显示 |

- 共享电脑打开后直接展示录音组件，不输入或保存用户名
- 录音完成并上传成功后（`AudioRecorder` 组件 `@uploaded` 事件）：`step = 'image'`，右栏展示双栏上传选项：
  1. **电脑拍照**：使用 `CameraCapture` 组件，通过 `getUserMedia` 打开摄像头，实时预览 + 点击拍照 + 自动上传
  2. **扫码上传**：展示二维码，指向 `/upload-image/{filename}`（手机扫码上传图片）
  3. 两个选项之间显示「或」分隔符（黑色、20px）；两个选项卡片等高同宽（`align-items: stretch`），预览区尺寸均为 200 × 150
- 右栏内容切换用 `<Transition name="pane-swap" mode="out-in">`：旧内容向左滑出，新内容从右滑入
- 轮询同步机制：
  - 进入 `image` 后每 3 秒轮询 `HEAD /api/image/{base}.{ext}`，依次尝试所有允许的图片扩展名（`.jpg`, `.jpeg`, `.png`, `.webp`）
  - 轮询到图片存在（HTTP 200）后停止轮询，将图片 URL 传入 `QrCodeCard` 并切到 `card`
  - 两种触发（拍照成功 / 轮询命中）都走 `showCard()`，重复触发会被 `step === 'card'` 拦住
  - 页面上没有「跳过」按钮，不配图就无法进入明信片阶段
- `card` 阶段右栏显示 `QrCodeCard.vue`，传入 `audioUrl`, `filename`, `imageUrl`（如有），明信片包含音频二维码 + 波形图 + 可选图片
- 收到 `QrCodeCard` 的 `printed` 事件后走 `resetCreation()`：清空数据、`step` 回到 `record`（电话亭滑回屏幕中央）、`recorderKey++` 重挂录音组件
- 单屏保障：窗口小于 1200 × 700 时，`updateStageScale()` 给 `.stage` 加 `transform: scale(min(1, innerWidth / 1200, innerHeight / 700))`，防止小窗口下按钮被裁掉

### 6.8 `CameraCapture.vue`

- 供 `HomeView.vue` 使用，提供电脑端摄像头拍照功能
- Props: `audioFilename`（必填）
- Emits: `captured({ url, filename })` — 拍照并上传成功后触发
- 使用 `navigator.mediaDevices.getUserMedia()` 打开摄像头，实时预览为镜像画面（`facingMode: 'user'` 的自拍视角）
- 流程：点击拍照按钮 → canvas 捕获当前视频帧（同样做左右镜像，保证成片与预览一致）→ 转为 JPEG（quality 0.9）→ 自动上传到 `POST /api/upload-image`（携带 `audio_filename`）
- 镜像只影响电脑拍照，手机扫码上传的图片保持原样，不做任何翻转
- 代价：照片中的文字、胸牌等会左右翻转，这是镜像成片的固有结果
- 三种 UI 状态：加载中（spinner）、不可用（权限拒绝/无摄像头错误提示）、就绪（视频预览 + 拍照按钮）
- 上传中按钮禁用，防止重复点击
- 修复要点：`cameraLoading = false` 需在 `srcObject` 赋值前执行，配合 `nextTick()` 确保 `<video>` 元素已渲染到 DOM

### 6.9 `SiteFooter.vue`（全站页脚）

- 首页、播放页、我的统计页、手机图片上传页都引入，统一提供底部信息

## 8. 打印策略

明信片通过**单页 PDF**打印，避免 HTML 页面被 Chrome 插入时间、网址和页码：

1. 用户点击“打印明信片”按钮 → `QrCodeCard.print()`，同步打开一个临时预览页以避免被浏览器拦截。
2. 前端将背景、可选图片、波形 Canvas 和音频二维码合成到与底图相同的 2500 × 1689 Canvas。
3. 按需加载 `jspdf`，生成一页固定为 148mm × 100mm 的 PDF，并替换临时页为 PDF 预览。
4. 用户在 PDF 查看器中点击打印；PDF 成功打开后首页立即重置，服务器不保存 PDF 文件。

## 9. 当前状态与本地验证

当前代码已实现共享电脑录音、打印版 PDF 打开后页面复位、可选图片关联（电脑拍照或扫码上传）、图片轮询同步、播放二维码、个人已听去重统计、凭证图片、波形绘制与 148mm × 100mm 明信片 PDF。仓库包含已听去重的最小单元测试和 Debian 部署说明，但没有端到端测试或自动化部署配置；发布及真实设备上的录音、扫码和打印结果需要在目标环境手动验收。
