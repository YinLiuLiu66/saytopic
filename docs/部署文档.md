# SayTopic Debian 部署文档

本文用于在 Debian 服务器上部署 SayTopic。正式环境不使用 `pnpm dev` 或 `pnpm preview`：

- Nginx 提供 `frontend/dist` 中的前端静态文件
- Nginx 将 `/api` 转发到本机 `127.0.0.1:8000`
- systemd 管理 Uvicorn，负责开机启动和异常重启
- 公网入口必须使用 HTTPS，麦克风和摄像头才能正常工作

## 1. 环境要求

- Git
- Nginx
- Python 3.11 或更高版本
- uv
- Node.js `20.19+` 或 `22.12+`
- pnpm `11.9.0`

先确认命令可用：

```bash
git --version
nginx -v
python3 --version
uv --version
node --version
pnpm --version
```

Debian 可先安装基础软件：

```bash
sudo apt update
sudo apt install -y git nginx
```

Node.js、pnpm 和 uv 请使用各自官方安装方式，避免 Debian 软件源中的版本低于项目要求。

## 2. 获取代码并构建

以下示例假设项目位于 `/srv/saytopic`。先运行 `whoami` 确认部署用户，并将 `<部署用户>` 替换为该用户名；使用其他目录时，同步替换后续配置中的路径。

```bash
whoami
sudo mkdir -p /srv/saytopic
sudo chown <部署用户>:<部署用户> /srv/saytopic
git clone https://github.com/YinLiuLiu66/saytopic.git /srv/saytopic
cd /srv/saytopic

cd frontend
pnpm install --frozen-lockfile
pnpm build

cd ../backend
uv sync --frozen
uv run python -m unittest test_stats.py
```

构建完成后，前端文件位于 `/srv/saytopic/frontend/dist`。

## 3. 配置后端 systemd 服务

先获取 uv 的绝对路径：

```bash
command -v uv
```

创建 `/etc/systemd/system/saytopic.service`，将 `<部署用户>` 和 `<uv绝对路径>` 替换为服务器上的真实值：

```ini
[Unit]
Description=SayTopic FastAPI
After=network.target

[Service]
Type=simple
User=<部署用户>
WorkingDirectory=/srv/saytopic/backend
ExecStart=<uv绝对路径> run uvicorn main:app --host 127.0.0.1 --port 8000
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

启动并检查：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now saytopic
sudo systemctl status saytopic
curl -fsS http://127.0.0.1:8000/openapi.json -o /dev/null
```

查看后端日志：

```bash
sudo journalctl -u saytopic -f
```

运行服务的用户必须能写入 `/srv/saytopic/backend/uploads`，否则录音、图片和统计数据无法保存。

## 4. 配置 Nginx

创建 `/etc/nginx/sites-available/saytopic`：

```nginx
server {
    listen 8080 default_server;
    server_name _;

    root /srv/saytopic/frontend/dist;
    index index.html;
    client_max_body_size 12m;

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

启用并检查：

```bash
sudo ln -s /etc/nginx/sites-available/saytopic /etc/nginx/sites-enabled/saytopic
sudo nginx -t
sudo systemctl reload nginx
curl -I http://127.0.0.1:8080/
curl -fsS http://127.0.0.1:8080/api/openapi.json -o /dev/null
```

`try_files ... /index.html` 用于支持 `/play/...`、`/mine` 等 Vue 路由直接访问或刷新。

## 5. 配置公网 HTTPS

### 使用现有 frp HTTPS 地址

如果 `https://frp-off.com:23506` 已由 frp 服务提供有效 HTTPS 证书，将隧道的本地目标从 Vite 的 `5173` 改为 Nginx 的 `8080`：

```text
公网 https://frp-off.com:23506
  → frp
  → 127.0.0.1:8080（Nginx）
  → /api 转发至 127.0.0.1:8000
```

不要再把正式流量转发到 `pnpm dev`。

### 使用自己的域名

将 Nginx 的 `listen 8080` 改为 `listen 80`，把 `server_name _` 改为真实域名，然后使用 Certbot 或其他受信任证书方案启用 HTTPS。证书生效后再用正式域名测试麦克风和摄像头。

如果公网来源不再是 `https://frp-off.com:23506`，还要同步检查：

- `backend/main.py` 中的 CORS 来源
- `frontend/vite.config.js` 中仅供开发服务器使用的 `allowedHosts`

生产环境由 Nginx 同源提供前端和 `/api` 时，浏览器通常不会触发跨域请求。

## 6. 上线验收

在公网 HTTPS 地址逐项检查：

1. 电脑打开首页，允许麦克风并完成一次录音。
2. 分别测试电脑摄像头拍照、手机扫码上传图片和跳过图片。
3. 生成明信片，确认二维码使用公网 HTTPS 地址。
4. 手机扫描播放二维码，输入用户名并开始播放。
5. 重复播放同一录音，确认“已听”数量不重复增加。
6. 扫描另一条录音，确认数量增加一条。
7. 打开“我的统计”，生成凭证图片并长按保存。
8. 打开打印预览；关闭系统打印窗口后，确认共享电脑页面恢复初始状态。
9. 重启后端，确认已有录音、图片和统计仍然存在。

## 7. 更新部署

```bash
cd /srv/saytopic
git pull --ff-only

cd frontend
pnpm install --frozen-lockfile
pnpm build

cd ../backend
uv sync --frozen
uv run python -m unittest test_stats.py

sudo systemctl restart saytopic
sudo nginx -t
sudo systemctl reload nginx
```

更新代码不会删除 `backend/uploads`。正式活动前如需清空测试录音、图片和统计数据，应先备份，并在明确确认后单独执行。

## 8. 常用排查

```bash
sudo systemctl status saytopic
sudo journalctl -u saytopic -n 100
sudo nginx -t
sudo tail -n 100 /var/log/nginx/error.log
curl -fsS http://127.0.0.1:8000/openapi.json -o /dev/null
curl -I http://127.0.0.1:8080/
```

- 网页能打开但 `/api` 报错：检查 Uvicorn 状态和 Nginx `/api/` 代理。
- 麦克风或摄像头不可用：确认浏览器地址栏是 HTTPS，或同机使用 `localhost`。
- Vue 子页面刷新后 404：检查 Nginx 的 `try_files`。
- 上传返回 413：检查 `client_max_body_size 12m` 是否已生效。
- 文件无法保存：检查 systemd 服务用户对 `backend/uploads` 的写权限。
